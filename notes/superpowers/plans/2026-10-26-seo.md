# SEO pass — implementation plan

Spec: `notes/superpowers/specs/2026-10-26-seo-design.md`. Worktree:
`worktrees/github.com/donaldfilimon/quesar.cloud/seo-20261026`, branch `task/seo-20261026`.
Each task: tests first (vitest, `node` environment, `renderToStaticMarkup` for
`.tsx`), `bunx prettier --write` on touched files, `bun run typecheck`, `bun run lint`,
the touched tests, then one conventional commit ending with the repo's
`Co-Authored-By` line. Never edit `docs/` or generated `app/` by hand.

1. **Indexing.** `ServerOnlyNotice` full variant renders `<meta name="robots"
   content="noindex" />`; add `noindex` to the `head()` of `/console`,
   `/console/workspace`, `/dashboard`, `/profile`. Tests: notice markup contains the
   meta; route heads contain it. Files: `src/components/site/server-only-notice.tsx`,
   the four route modules, tests beside them.
2. **Site-wide JSON-LD and breadcrumbs.** In `src/lib/mlai/structured-data.ts` add
   `siteGraphLd()` (`WebSite` + `Organization`, `@id`s `https://quesar.cloud/#website`
   and `#organization`, the home `sameAs`) and `breadcrumbLd(pathname, title)`. Put the
   graph in `rootHead.scripts`; drop the home route's own Organization; render the
   breadcrumb in `HeadTags` for canonical non-root pages (section labels from
   `nav` in `src/lib/site-identity.ts`, else title case; last item is the page title
   minus a trailing ` · Quesar`/` — Quesar` suffix). Tests for both builders and for
   `HeadTags`/home head output.
3. **Index-page ItemLists.** `collectionPageLd(path, name, description, urls)`; emit it
   from the `head()` of `/blog`, `/research`, `/docs`, `/products`, `/projects`, `/team`
   using the same content modules those pages render. Tests per builder; check bundle
   impact with `check:static`.
4. **Metadata.** In `src/lib/seo.ts`: `clampDescription` (≤160 at a word boundary,
   trailing `…`) used by `pageHead` for meta/OG/Twitter descriptions; `seoTitle` adds
   ` · Quesar` to titles under 30 characters that do not contain "Quesar" or "MLAI".
   Fix the three duplicate research descriptions and extend short descriptions only
   from text already in the same record (content modules under
   `src/lib/mlai/categories/`, `src/lib/mlai/pages.ts`); every changed sentence goes
   through the `claims-auditor` agent. Tests for both helpers.
5. **Headings for client-only routes.** For `ssr: false` routes and app routes without
   an `<h1>` in their static HTML (`/showcase/*`, `/quasar/*`, `/tf-pose-demo`), render a
   visually hidden `<h1>` from the route title in the static markup, only where the
   hydrated page has none. Test with the route's static render.
6. **llms.txt.** `src/lib/llms-txt.ts` (`buildLlmsTxt()` from the search catalog and
   `site`) plus hand-written `app/llms.txt/route.ts` (`force-static`, `text/plain`).
   Link it from `robots.txt` generation only if `publish-static` already owns robots
   (comment, not a directive). Tests for the builder.
7. **SEO gate.** `scripts/check-seo.ts` with pure, exported checks and
   `scripts/check-seo.test.ts`; `package.json` `check:seo`; mention it in the
   `quesar-static-publish` skill step 4 and in `CLAUDE.md` commands.
8. **Integrate and publish.** `bun run check`, `bun run build:static`,
   `bun run check:static`, `bun run check:seo`, `bun run test:e2e`; publish recipe step 3
   comparison against the committed `docs/`; commit `build(docs): rebuild the static
   site for the Next.js export and SEO pass`; PR to `main`, merge, verify the live
   site serves the new pages.
