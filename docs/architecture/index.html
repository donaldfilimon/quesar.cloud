Reading the diagram

Input, processing, memory, retrieval, execution, tools, output.

The layers are a map, not a marketing stack. If a name sounds larger than the implementation, the status label is the correction.

  1. 01

    User → Quesar

    A local workspace, CLI, or companion issues a request. Quesar is the product envelope, not a hosted brain.

  2. 02

    Quesar → ABI + tools

    ABI routes the request, assembles inspectable context, and may invoke contract-covered plugins.

  3. 03

    Model router + context

    An exact registry model and device are selected. Context is assembled before execution, not hidden after.

  4. 04

    WDBX

    Durable records, embeddings, and provenance live here. Retrieval can return what happened and why a record is trusted.

  5. 05

    Local / edge / remote compute

    CPU SIMD is the honest fallback. Remote providers are optional. Nothing on this website is a compute plane.

  6. 06

    Output

    A response, a plan, a tool result, or a refusal. Abbey will not claim what the ledger cannot prove.
