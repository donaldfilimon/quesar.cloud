Trust boundary

Configured console Chat: three boundaries.

The server-side console Chat path checks identity, provider configuration, and audit storage within one request. Broader runtime control-plane work has separate status and acceptance requirements.

●Current

Account-scoped access

Protected console functions use Better Auth sessions and scope per-user records by user id. Admin access requires an allowlisted email and a linked Google or Apple account. Public inquiry and configuration functions have separate controls.

●Current

One server-side model interface

Website model requests use a server-side interface configured for xAI or Cloudflare AI Gateway to Gemini. Console Chat checks provider availability and a per-user rate limit; the request builder does not automatically add account email. Provider and deployment acceptance require separate evidence.

●Current

Records you control

Conversation audits and workspace refresh tokens are sealed with AES-256-GCM under APP_ENCRYPTION_KEY, bound to their owner and purpose. Console Chat requires current audit consent and stores its sealed exchange before returning a reply. Contact inquiry fields are stored separately and are not covered by this application-level sealing.

One request

Five checks for console Chat.

In the configured server console Chat path, authenticate, consent, generate, encrypt, and store the audit before returning the reply. These checks are implemented in source. The static preview has no server chat, and live deployment acceptance requires separate evidence.

Inspect the security model
  1. 01

    Authenticate

    ●Current

    The protected console Chat function requires a Better Auth session and uses that user's id. This requirement does not apply to every public server function.

  2. 02

    Consent

    ●Current

    Console Chat requires acceptance of the current audit policy before its provider request. Other website features have their own data and permission boundaries.

  3. 03

    Generate

    ●Current

    Console Chat requires a configured provider and checks a per-user rate limit before generation. The server request does not automatically include account email.

  4. 04

    Encrypt

    ●Current

    Console Chat refuses without a valid audit-encryption key. Its prompt and reply are sealed with AES-256-GCM, bound to the audit owner.

  5. 05

    Commit

    ●Current

    Console Chat stores the sealed audit before returning a successful reply. If audit storage fails, the generated reply is withheld.

Product boundary

An experimental local builder.

The Quasar browser client pairs with an operator-owned service that scaffolds Next.js projects and uses a configured provider for generation. Live provider generation remains unverified. ABI, WDBX, and Abbey have separate source and integration boundaries.

What it is

Quesar's available source surface is the experimental Quasar website builder: a browser client paired to a separately running operator-owned service. Generation uses a configured provider; live provider acceptance remains unverified.

Separate acceptance boundaries

Builder source does not establish a trained Quesar foundation model, a hosted Abbey product session, compliance certification, or a performance result. The configured website console is a separate model-request path.
